## Capture limitations and historical results

- 62 images: 24 actual UI captures, 33 labeled saved-output views, four configuration views and one design view. All 51 earlier images and their historical successes/failures remain unchanged.
- New local production access uses service port-forwards and a temporary same-origin proxy. No production Ingress/TLS, public domain, cloud deployment or Argo prod synchronization was exercised.
- Full web stacks were tested sequentially. Both small database instances were kept briefly for bidirectional isolation controls; this is not proof of concurrent full-stack operation.
- Earlier db2efa8 main promotion FAILED. Later ef41449 main publication and promotion PASSED. The guarded helper in open PR18 still needs a hosted main execution after merge; these are distinct facts.
- New E52/E53/E56 are actual GitHub/application UIs. E54/E55/E57–E62 are labeled archived real outputs, captured before cleanup. No archived output is presented as a live terminal.
- Historical source documents are frozen when current documentation changes, preserving the original provenance hash. New metadata is in additional-evidence.json; old screenshot bytes are never regenerated.
- The node had a 2 GiB cap, no monitoring/Argo stack and no image builds. Minimum sampled available RAM was 1667 MiB; sampling was restarted and is not claimed to be uninterrupted.
- Only task-owned cluster/data/helpers were removed. Unrelated Jenkins containers were preserved; generated test credentials and kubeconfig were removed.
- Prior GitOps rollback proves configuration restoration and record continuity, not image/schema downgrade or full disaster recovery.
