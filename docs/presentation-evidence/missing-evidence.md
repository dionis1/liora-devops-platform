## Capture limitations and historical results

- Older terminal sessions/clusters were gone; their real saved output is shown in labeled archived-output views. New Argo/GitHub/package screenshots are actual UIs. Kubernetes/registry output views are labeled and backed by full artifacts.
- Earlier private Git authentication and package metadata failures remain dated history. Current public Git reconciliation, anonymous GHCR reads and matching running digests passed; no deploy key or registry credential was required.
- Main db2efa8 passed tests/scans/publication but failed promotion on a merge conflict. The reviewed local recovery advanced deploy/dev successfully; no green complete main run is claimed. The new helper's hosted main execution remains pending after merge.
- The bounded local Argo test succeeded with a 2 GiB node cap, four Argo components, no monitoring, and a memory watchdog. Its minimum measured available RAM was 1204 MiB. The old 3 GiB conservative gate is historical, not a claim that this later test was skipped.
- The rollback was a controlled pod-template change and Git revert on a real isolated GitHub branch. It proves configuration restoration and data continuity, not image-version downgrade, schema rollback or k3s/cloud restoration.
- The temporary cluster, port-forwards and generated credentials were removed after capture. The successful screenshots are dated execution proof, not a claim that Argo is still running.
